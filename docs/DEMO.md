# CLI demonstration

From the prepared checkout, run `frameshrink start transaction`. Docker must be running. Pick a CLI wallet or create a named wallet, request faucet funds if needed, select TIMESTAMP and NUMBER, and choose a combined transaction. Approve validator setup if requested. At the transaction preview, press O then Enter to inspect the decoded frames in your editor; C continues to the original submission confirmation. The command creates a new case directory automatically.

1. Show the owner-bound validator and the real public TIMESTAMP rejection.
2. Start debugging; show TIMESTAMP and then the exposed NUMBER failure.
3. Show each streamed local check and the measured smaller fixture, with the failure preserved.
4. Show clean replay of the exact signed payloads under reconstructed relevant state.
5. Review the expanded terminal change summary; O opens the full change report. Confirm the corrected submission and show its real public admission and successful receipt.
6. Share the case and replay it with `frameshrink replay <case-directory>`; no signing key is needed.

The recorded completed demo reduced 4 frames / 767 bytes to 2 frames / 282 bytes in six evaluations. Both corrected public frames succeeded in block 5291. Use `frameshrink demo status evidence/unified-demo` to review saved results without a new transaction, or replay that saved case locally.

The correction changes the validator input to skip TIMESTAMP. It retains signer/chain/nonce binding and is distinct from removing irrelevant body calls/data. Public writes are bounded test transactions; candidates run locally. The pinned local environment reconstructs the account state this recipe needs, not the entire public chain or unknown public policy.
